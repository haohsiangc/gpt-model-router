# Codex 模型路由｜安裝與使用手冊

**分享版：2026-11-18 · 適用於 macOS 上的本機 Codex CLI 與 Desktop**

這套設定讓 Sol 負責主對話，把可獨立完成的工作分給合適的子代理。平常直接描述任務即可，不必每次挑模型。它不會安裝模型、開通帳號權限，也不需要另外執行 Python router。

## 先看分工

| 遇到的工作 | 角色 | 模型與推理強度 |
| --- | --- | --- |
| 釐清需求、拆解任務、整合與最後審查 | Lead | GPT-6.2 Sol · high |
| 整理格式、分類、抽取欄位等有明確規則的工作 | routine_worker；未指定角色時也用這組 | GPT-6.1 Terra · medium |
| 一般開發、除錯、測試 | ordinary_worker | GPT-6.2 Sol · medium |
| 跨模組推理、架構取捨、難解的局部問題 | frontier_solver | GPT-6.2 Sol · max |
| 嘗試不同方法後仍無解，或確實需要更強推理的最小問題 | exceptional_solver | GPT-6.2 Astra · xhigh |

不是每個任務都要跑完五層。小事由 Lead 直接做；需要專家時，只交出卡住的部分。Terra low、Astra max 只在使用者明確指定時使用。

## 安裝前：我的帳號能用嗎？

原始環境已用 CLI 0.170.0 驗證上述路由，並在 Desktop 確認能派出 Terra medium。這不是最低版本保證，也不代表所有帳號都可用。每位接收者都要用自己的帳號驗證。

1. 在終端機執行 `codex --version`，再用 `codex debug models` 查三個模型 ID 與支援的強度。Desktop 和終端機可能用不同版本。
2. 在空目錄執行以下唯讀測試。這會使用自己的模型額度；正確回覆是 437。依上表替換模型與強度即可測其他組合。若出現 `model_not_found` 或不支援該強度，先停止安裝，確認版本和帳號，不要把不能用的 Lead 設成預設。

```sh
codex exec --ignore-user-config --ephemeral --skip-git-repo-check -s read-only \
  -m gpt-6.2-sol -c 'model_reasoning_effort="high"' '請勿使用工具，只回答 19 × 23。'
```

## 安裝：合併設定，不要覆蓋整個資料夾

先解壓縮。下表使用預設個人路徑；若有自訂 Codex 設定目錄，先確認兩個客戶端各自讀哪裡。這是全域設定，可能影響其他專案的新對話。

| 包內檔案 | 安裝位置 | 處理方式 |
| --- | --- | --- |
| config.routing.toml | ~/.codex/config.toml | 僅合併兩個頂層鍵和三個 agents 鍵 |
| AGENTS.md | ~/.codex/AGENTS.md | 合併政策，保留其他規則；舊路由段落應替換而非重複追加 |
| agents/ 內四個 TOML | ~/.codex/agents/ 下的同名檔案 | 逐檔比對，保留其他角色 |
| skills/model-routing-policy/SKILL.md | ~/.agents/skills/model-routing-policy/SKILL.md | 安裝到同名目錄；已有自訂內容時先比對 |

**用 Codex 協助安裝：** 在解壓後的資料夾開始對話，貼上以下要求。若要手動安裝，也按同一順序處理。

> 先唯讀檢查本機版本、帳號可用模型、既有設定與這個分享包。依 README 的對照表列出要改的檔案；如有不支援的模型、同名角色衝突或須取代舊 router，先停下來問我。修改前建立私人備份，保存七個目標的原始內容與相對路徑，記錄原本不存在的項目。經我確認後只合併路由，不改 MCP、權限、登入、通知、PATH 或其他設定。最後用新工作階段驗收，回報實際選到的模型、推理強度和還原方式。不要將本機備份加入分享包。

**手動合併 TOML 的關鍵：** 如果已有 `model` 或 `[agents]`，更新原鍵，不要再貼第二份。檔案前兩個模型鍵要在第一個表頭之前；放在 `[agents]` 下會改變意思。若沒有既有設定，才可把片段作為新的 config.toml。缺少的目錄可自行建立。

## 驗收：怎麼知道真的分派了？

1. 另開 **CLI 新對話**。在空目錄執行 `codex exec --strict-config --skip-git-repo-check -s read-only '不使用工具，只回答 2+3。'`。不要加 `-m` 或強度覆寫。預期啟動資訊為 Sol high，答案為 5。
2. 在新對話貼下方測試。這是刻意檢查角色映射，不是測模型的數學能力；會產生五次子代理用量。

> 分兩批派出五個子代理，不指定模型或推理強度，不讀寫檔案，不再委派。第一批分別讓 routine_worker、ordinary_worker、frontier_solver 計算 12+1、12+2、12+3。收齊後，讓 exceptional_solver 計算 12+4，最後一個不指定角色，計算 12+5。等全部回來再列出結果。

3. 預期結果為 13、14、15、16、17。從執行資訊或工作階段紀錄核對各子代理的角色、模型及強度是否符合分工表；答對數字或代理自報型號都不算選型證據。若客戶端不顯示該資訊，就記為「任務成功、型號未驗證」。
4. 在 **Desktop 新對話**至少測一次：「請讓 routine_worker 計算 17 × 13，不覆寫模型或強度。」預期 221，子代理為 Terra medium。CLI 成功不代表 Desktop 已載入；若不同，先檢查帳號、設定目錄、專案規則及對話是否指定了其他模型。

## 日常使用：什麼時候需要我切模型？

例如「請幫我把這份表格的欄位名稱統一，並指出無法判斷的欄位」適合 Terra；「找出測試偶爾失敗的原因」可直接交給 ordinary_worker。需要更強的子代理時，Lead 自動分派，不必手動換主模型。

只有下一步必須換 **Lead**、自動分派不能滿足需求，且已確認目標可用時，才會暫停並顯示文字提示：

> **需要你手動切換｜目標：模型 · 推理強度**  
> 原因：為什麼必須換主對話，而不能只派子代理。  
> 操作：目前 CLI 或 Desktop 已確認可用的操作。  
> 切換後：從哪一步繼續；若要開新對話，先提供可貼上的交接摘要。

這是對話規則，不是彈窗。收到提示不代表已切換；若帳號沒有該型號，請回報限制，不要猜選其他模型。

## 還原與再分享

要撤回時，對照安裝前的清單，逐檔還原。若安裝後又改過其他設定，只撤回路由差異，不要用舊備份覆蓋後續工作。原本不存在的檔案可先移到私人備份，再開新對話確認原有行為；不用刪除整個 ~/.codex。

分享時只轉傳原始 ZIP。**不要打包自己的 ~/.codex、登入資料、執行紀錄或私人備份。** 接收者自行安裝與登入即可。
